## 2. Region switch — what is scaffolded in code

Already in `scripts/main.gd` (chunk 2, no behaviour change):

```gdscript
const REGIONS := {"mines": 0, "fungal_hollows": 1}

func _region_seed(region_id: int) -> int:
    if region_id == REGIONS["fungal_hollows"]:
        return run_seed + 100000
    return run_seed
```

Seed rule: region 1 derives `run_seed + 100000`, so the Hollows layout is
stable per run but can never collide with the Mines layout for the same
`run_seed`. The Mines path calls `_region_seed(REGIONS["mines"])`, which
returns `run_seed` unchanged — current behaviour is untouched.

## 3. Region switch — design (not built)

Two options for how region 2 exists. Neither is picked here.

**Option A — separate world (recommended by simplicity).** A Hollows run is
its own world: `DeepfallMapGen.generate(_region_seed(1))`, same 200×90
shape, its own rooms/legs/spawn/exit. The region is chosen at new-run
(a region field in the save + a select step). Pros: save versioning stays
clean (one region per save), the exit can gate back to the Mines or to a
Hollows exit, and no Mines layout code changes. Cons: travelling between
regions is a load, not a walk.

**Option B — same world, eastern region.** The Hollows are rooms beyond a
boundary in the same 200×90 world (e.g. x > 160), generated by the same
`generate()` with a region mask per room. Pros: walking between regions,
one continuous map. Cons: `map_gen.gd` needs per-room region tags, the
flood-fill / connectivity checks must span the boundary, and the save
format must record which region each delta belongs to (mined cells,
torches, props).

Whichever option is picked, the region is keyed by a `region` var on the
main node (default `REGIONS["mines"]`), set before `_rebuild_world()` and
read by the tile/material/enemy code — never by a global.

## 4. File layout for the full build

- `scripts/map_gen.gd`: `generate(seed)` gains a region parameter (A) or a
  per-room region mask (B). Region-2 room/leg generation reuses the same
  generator with the derived seed — no second generator.
- `scripts/main.gd`: new fg ids for the fungal materials (next free ids
  after 13), `_mat_group()` gains a fungal family (or the fungal fills join
  the dirt family — a design call: separate family needs a fungal
  transition set, joining dirt reuses the existing rock↔dirt transitions),
  atlas wiring in `_build_tileset()` (16 tiles + transitions + inner/outer
  corners, same pattern as chunk 2), `mushroom-platform` as a one-way
  platform (new id, same `_platform()` rule as id 7).
- `assets/tiles2/fungal_*.png`: the 16 sliced tiles, copied in by a
  `build_hollows_assets.py` in the Phase 9 / chunk-2 style (PIL only,
  staged sources copied, never moved). The 400px sources are downscaled,
  not the 64px RGB files, where alpha is needed.
- `scripts/` (enemies): a `fungal-sunken` slug + spawn-table entry, built
  from the walk/attack strips the same way the skeleton-warrior was built
  from KayKit GLB bakes (Phase 13 pattern).
- Save: `SAVE_VERSION` 8 → 9 for the `region` field. **Coordinate with the
  Shift capstone, which plans v10** — do not bump to 10 here and collide
  with it.
